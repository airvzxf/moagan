# `moagan` v0.5 — Roadmap: hot path completion

> **Status**: proposed
> **As of**: 2026-08-06
> **Base**: `5d18d5e` (PR #219) + `7950fce` (docs commit)
> **Purpose**: close the integration debt left by 100+ PRs that landed
> with code + tests but no hot-path caller, and align `moagan discover`
> with V4 §6 / T01-06 §9.

---

## 1. Contexto

`moagan v0.4` está cerrado como **catalog wiring + housekeeping**
(HEAD `5d18d5e`, 2026-08-06, 1508 lib + 22 integration tests pasando,
gauntlet 7/7 verde). El reporte final declara "100+ PRs mergeados"
pero una auditoría cruzada del código revela que **al menos ~30 items
del catálogo D.x y de la spec T01-06 llegaron como struct/función +
tests sin caller de producción**. Adicionalmente, `moagan discover`
está implementado al ~70% del spec V4 §6: la pipeline plana corre
los 10 phases, pero `DiscoveryCoordinator`, stop policy, outlier
tracker y checkpoint humano único están ausentes o son dead code.

Este roadmap ataca los **29 PRs** que cierran esa deuda sin añadir
features nuevas. Output esperado: binario rotulable como
"v0.5 production-grade" con el catálogo D.x pasando de ~67% a ~85%
cerrado **y wirado**, no sólo declarado.

### Convención de tags

- `[WIRE]` — código existe + tests, falta caller en hot path.
- `[GAP]` — feature entera ausente.
- `[LIMIT]` — limitación reconocida por el propio repo.
- `[SPEC-DRIFT]` — divergencia spec ↔ implementación.
- `[DEFER]` — explícitamente v0.6+ (no en este roadmap).

### Convención de prioridad

- `HIGH` — bloquea narrativa de "production-ready".
- `MED` — mejora material de UX o cobertura.
- `LOW` — polish; se cierra porque es barato, no porque bloquee.

### Convención de esfuerzo

- `S` — 1 PR, ≤300 líneas diff, sin cambio de arquitectura.
- `M` — 1 PR, ≤800 líneas, refactor acotado.
- `L` — 1+ PR, >800 líneas o cambio arquitectónico.

## 2. Resumen de las 3 fases

| Fase | Foco | PRs | Effort | Riesgo |
|---|---|---:|---|---|
| **A.1** | Hot-path wire-up de helpers schema-only | 15 | ~10-15 días | Bajo |
| **A.2** | Discovery fidelity (V4 §6 / T01-06 §9) | 9 | ~7-10 días | Medio |
| **A.3** | Limitaciones reconocidas + polish | 5 | ~3-5 días | Bajo |
| **Total** | | **29** | **~25-35 días** | |

No hay dependencias hard entre A.1, A.2 y A.3 — los PRs dentro de
cada fase sí. La Fase A.1 es trabajo concentrado de bajo riesgo
(lo primero que se ataca). La Fase A.2 toma la decisión sobre
matrix shape (PR-16) como primer paso porque determina el resto.
La Fase A.3 es independiente y se cierra en cualquier momento.

## 4. Fase A.2 — Discovery fidelity (9 PRs)

Alinea `moagan discover` con V4 §6 / T01-06 §9. Empieza por la
**decisión arquitectónica** sobre matrix shape (PR-16) porque
determina la forma de los siguientes PRs.

#### PR-16 · `[SPEC-DRIFT·S·HIGH]` — Decisión: matrix shape

- **Spec ref**: V4 §6.4, T01-06 §9.1
- **Estado actual**: spec dice `roles × models × temperatures`;
  impl dice `dimensions × facets × per_cell`
  (`src/discovery/matrix.rs:36`).
- **Cambio (recomendado)**: documentar la divergencia en
  `docs/proposal-03-add-ons.md §D.9.1` como evolución intencional
  (la spec era teorética; la impl es lo que funciona en practice).
  La matriz `dimensions × facets × per_cell` es más flexible porque
  no requiere un provider distinto por celda.
- **Cambio (alternativo)**: añadir `model_spec: Option<ModelSpec>`,
  `role: Option<Role>`, `temperature: Option<f32>` por celda en
  `MatrixCell`, y cablearlos al LLM call. Reescribe la mitad del
  discovery.
- **Recomendación**: opción 1 (doc). Si surge un caso real donde
  la divergencia duele, se ataca opción 2.
- **Test**: ninguno (es doc + decisión).
- **Verificación**: el commit message incluye la decisión y referencia
  el issue tracker.

#### PR-17 · `[WIRE·L·HIGH]` — `DiscoveryCoordinator` wire-up

- **Spec ref**: V4 §6.3, D.13.6
- **Estado actual**: `src/discovery/coordinator.rs::DiscoveryCoordinator`

- **Test**: integration test que ejecuta `moagan discover --cardinality 80`

- **Verificación**: `telemetry.jsonl` muestra que cada fase es
  invocada por el coordinator (no por el pipeline runner).
- **Esfuerzo L** por la paridad con el pipeline actual.
- **Dependencia**: bloqueado por PR-19 (stop policy) para que el
  coordinator pueda invocar `StopDecision`.

#### PR-19 · `[GAP·L·HIGH]` — Stop policy + outlier tracker

- **Spec ref**: V4 §6.4, T01-06 §9.3, D.13.1/.2/.3/.7/.8
- **Estado actual**: `SaturationTracker` parcial en
  `src/discovery/saturation.rs` (PR #176); `StopDecision`, outlier
  tracker, `BlockReason` enum todos ausentes.
- **Cambio**: implementar
  - `StopDecision { Continue, Stop { reason: StopReason } }` enum.
  - `StopReason { Saturated, OutliersCollected, BudgetExhausted,

  - `detectar_outliers(samples, clusters) -> Vec<SketchId>` con

  - `BlockReason { InsufficientResults, AllModelsSaturated,
    BudgetExhausted, Cancelled }`.
  - Cablear `SaturationTracker::update(batch, clusters) -> StopDecision`

- **Verificación**: con `--cardinality 100` y saturación al 50%,

- **Esfuerzo L** porque es feature entera con varias invariantes.
- **Dependencia**: bloqueado por PR-16 (decisión matrix shape).

entre sí; se pueden paralelizar.

#### PR-25 · `[LIMIT·S·MED]` — `CancelTier::Hard` SIGTERM (D.10.1)

- **Spec ref**: D.10.1
- **Estado actual**: `CancelTier::{Soft, Normal, Hard}` colapsa
  al mismo `CancellationToken` cooperativo. Hard no envía SIGTERM.
- **Cambio**: en `cancel.rs::Hard`, además de cancelar el token,
  invocar `nix::sys::signal::killpg(...)` con `SIGTERM` y, tras
  5s grace, `SIGKILL` (ya tenemos `killpg` en sandbox).
- **Test**: integration test que lanza un sandbox child con sleep
  60s y verifica que `Cancel::hard()` lo mata en <6s.
- **Verificación**: `telemetry.jsonl::cancel` muestra
  `tier = "hard"` con `signal = "SIGTERM"` y `escalated = true`
  si pasó a SIGKILL.

#### PR-26 · `[LIMIT·S·LOW]` — `Compression::reader` multi-stream (D.7.5)

- **Spec ref**: D.7.5
- **Estado actual**: `Compression::reader` usa `GzDecoder`
  (single-stream); el writer de telemetría sigue usando
  `open_gz_read` con `MultiGzDecoder`. Asimetría intencional
  pero limitante para tooling que abre sidecars.
- **Cambio**: añadir `Compression::multi_reader(path) -> Box<dyn Read>`
  que usa `MultiGzDecoder` para `Gz`. Mantener `reader` para
  single-stream.
- **Test**: unit test que lee un multi-member gz con `multi_reader`.
- **Verificación**: ningún cambio de comportamiento; sólo nueva API.

#### PR-27 · `[LIMIT·S·LOW]` — `strip_control_tokens` centralizado (D.7.2)

- **Spec ref**: D.7.2
- **Estado actual**: sólo en `intake.rs` y SSE parser. No hay
  helper general.
- **Cambio**: añadir `src/llm/control_tokens.rs::strip(s) -> Cow<str>`
  que elimina `\u{0000}-\u{001F}` y `\u{007F}` excepto
  `\n \r \t`. Cablear en todos los parsers de LLM output.
- **Test**: unit test con fixtures de strings con BOM,
  zero-width, control chars.
- **Verificación**: ningún cambio de comportamiento en tests
  existentes; sólo más robustez.

#### PR-28 · `[LIMIT·S·LOW]` — `safe_path` helper (D.29.1)

- **Spec ref**: D.29.1
- **Estado actual**: canonicalización ad-hoc en algunos call sites.
  No hay helper central.
- **Cambio**: añadir `src/fs_layout.rs::safe_path(root, candidate) -> Result<PathBuf>`
  que rechaza `..` y symlinks fuera de root. Usar en todos los
  sitios que reciben `path` desde CLI o sidecar.
- **Test**: unit test con paths maliciosos
  (`../../etc/passwd`, `/etc/passwd`, `~/sensitive`).
- **Verificación**: un test que antes pasaba un path traversal
  ahora falla con `Error::PathTraversal`.

#### PR-29 · `[LIMIT·S·LOW]` — Centralized caps (D.29.2)

- **Spec ref**: D.29.2
- **Estado actual**: sólo `MAX_NORMALIZED_INPUT_BYTES = 256 KiB`
  en `intake`. No hay constantes para prompt / response / attachment.
- **Cambio**: añadir `src/llm/size_limits.rs` con
  `MAX_PROMPT_BYTES = 250 KiB`, `MAX_RESPONSE_BYTES = 10 MiB`,
  `MAX_ATTACHMENT_BYTES = 50 MiB`. Aplicar en intake y response.
- **Test**: unit test que payloads más allá del cap fallan con
  `Error::PayloadTooLarge`.
- **Verificación**: ningún cambio de comportamiento en tests
  existentes con fixtures dentro de los límites.
