## Layer 7 — Lefthook escape hatches (developer-side)

`lefthook.yml` doesn't skip any test by default. It offers three **escape hatches** that bypass hooks (the opposite of skip — they let the dev skip the validation entirely):

| Escape hatch | Effect |
|---|---|
| `LEFTPHOOK=0 git commit -m "..."` | Disable all lefthook hooks for one command |
| `git commit --no-verify` | Bypass pre-commit + commit-msg |
| `git push --no-verify` | Bypass pre-push (T2 cargo test still runs in CI) |

Source (extracted from `lefthook.yml` lines 13–20):

```yaml
# lefthook.yml — tiered validation hooks for moagan.
#
# The dev loop has four tiers. Each tier runs at a different moment so the
# common cases (fmt, clippy, build) are sub-30s while the slow integration
# suite (~minutes) only blocks push and CI.
#
#   T0  sub-second    fmt-check + guard-deps                → pre-commit (parallel)
#   T1  seconds       clippy + cargo build                  → pre-commit (parallel)
#   T2  minutes       cargo test --all-targets              → pre-push
#   T3  CI only       full gauntlet + smoke + e2e           → .github/workflows/
#   msg <1 s          conventional commit subject check     → commit-msg
#
# Skip flags (escape hatches — use sparingly):
#   LEFTPHOOK=0                    disable all hooks for one command
#   git commit --no-verify         bypass pre-commit + commit-msg (NOT recommended)
#   git push --no-verify           bypass pre-push (NOT recommended)
#
# First-time setup on a fresh clone:
#   pacman -S lefthook           # or: cargo install lefthook
#   lefthook install             # writes .git/hooks/{pre-commit,pre-push,commit-msg}
```

These do NOT affect CI — only local development. CI re-runs the full check from a clean state.

## Layer 8 — Process-wide env-locks (`TEST_*_LOCK` statics)

Tests that mutate process-wide state — `std::env::set_var`, `std::env::set_current_dir`, etc. — must serialise against any sibling test that reads the same state, or the parallel `cargo test` run surfaces as a flake.
