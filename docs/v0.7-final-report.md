## 1. TL;DR

v0.7.1 is **"CI e2e-network rebuild + runtime-probe auto-detected
`max_tokens` + minimax 524288 cap + Dependabot action refresh + three
patch releases (v0.6.1, v0.6.2, v0.7.1)"**. 17 PRs landed across four
waves (CI gauntlet, LLM provider, dependency / housekeeping, release
plumbing). All commits GPG-signed with `414687A3CD7E65B9` (airvzxf).
All T0/T1/T2/T3 gates green at merge time. The headline wins are
(a) the `e2e-network` restructure that cut the warm-cache build from
**270 s to 80–120 s** (#397) and fixed the silent stderr-swallow that
hid `moagan` exit failures in `fast` / `explore` / `card80` (#377, #389),
and (b) the auto-probe feature that discovers the real `max_tokens`
ceiling per `(provider, model)` pair at first startup and caches it
under `~/.local/share/moagan/max_tokens_auto.toml` (#400, #401). The
patch releases `v0.6.1` (5 PRs) and `v0.6.2` (5 PRs) absorbed the CI
repair work that did not need a new feature; `v0.7.1` ships the
runtime-probe fix that closes the loop on the `5xx
→ Indeterminate` failure class the probe surfaced.

## 3. CI / infrastructure changes

### Cluster A — e2e-network rebuild (#373, #375, #377, #383, #387, #389, #391, #394, #396, #397)

The v0.6.0 split into `card80` / `fast` / `explore` matrix rows (#338)
worked for the proof-of-life case but failed in production: the matrix
filter silently dropped the empty-input rows, the per-row timeouts
were tuned below the real-LLM job cost, the `moagan` exit code was
swallowed by the proxy stderr stream, and the `moagan-e2e-binary`
artifact landed in a location that no job could find. Each fix landed
as its own PR so the failure mode is bisectable from the git log.

- **#383 `build-once + per-job conditions`** — drops the single
  matrix strategy in favour of three explicit jobs (`card80`, `fast`,
  `explore`) that each build the binary on their own (via the
  `moagan-e2e-binary` artifact upload). The combined YAML diff is
  -66 / +101 lines in `.github/workflows/e2e-network.yml`.
- **#387 `add actions/checkout to e2e-network test jobs`** — the
  build-once / per-job precondition was missing `actions/checkout` in
  the test-job leg, so the artifact path was never re-anchored.
- **#389 `surface proxy startup error in fast/explore/card80
  tests`** — the upstream `proxy_e2e_matrix_stderr_swallows_test_failures`
  recipe outputs the proxy stderr stream but does not propagate the
  `moagan` exit code; the PR pipes `moagan` stderr / stdout into the
  job's captured stream so a `moagan` failure is visible in the job
  log.
- **#391 `extract moagan-e2e-binary artifact to target/release/`** —
  the artifact upload step put the binary in `target/release/` but the
  download step looked in `${{ github.workspace }}`. PR #391
  shortens the path so the binary is published into the workspace
  root via the upload's `path:` filter.
- **#394 `download moagan-e2e-binary to workspace root`** — the
  follow-up that mirrors the upload target on the consumer side; the
  artifact is now downloaded to `${{ github.workspace }}` (the job's
  default `cwd`).
- **#396 `explicit binary placement after artifact download`** —
  the download step writes to a `${{ matrix.binary }}` path; PR #396
  hard-codes the placement so the test scripts don't depend on the
  artifact's internal layout.
- **#397 `fix e2e-network warm-cache build (270s → 80-120s)`** — the
  headline perf win. The build job's restore-keys were too narrow, so
  the warm-cache hit rate was effectively zero. The new restore-keys
  partial-match `target/release/`, `target/release/deps/`, and
  `target/release/build/` so the cache reuses the dependency-build
  artefacts. First-build cold (no cache) ≠ 270 s; cached warm
  jobs now run in 80–120 s.
- **#373 `e2e-network template error from empty-input matrix filter`**
  — pre-flight fix for the matrix-filter cascade that started the
  regression cycle.
- **#375 `raise matrix row timeouts above real-LLM job cost`** — the
  `card80` row's `timeout-minutes` was below the real-LLM suite's
  wall-clock observation; PR #375 raises the per-row ceiling above
  the highest observed job (the real-LLM `card80` row).
- **#377 `surface moagan error in fast/explore e2e tests`** — same
  stderr-swallow fix as #389 but for the `fast` / `explore` row
  variants, completed before the matrix dropped in #383.

### Cluster D — release workflow cleanup (#385)

`ci(release): remove 3 deprecated action inputs (release warnings)`.
The `release.yml` workflow passed three action inputs that the
underlying actions had deprecated; the warnings cluttered the job
log and threatened future deprecation failures. PR #385 removes the
three inputs in three one-line deletions; no semantic change.

## 4. LLM provider changes

### Cluster B — runtime-probe `max_tokens` auto-detection (#379, #400, #401)

The hard-coded `MINIMAX_MAX_TOKENS_CAP` and
`OPENCODE_GO_MAX_TOKENS_CAP` constants in `src/llm/capabilities.rs`
were a regression vector: every time a vendor tweaked the upstream's
ceiling, the operator had to ship a new code patch. Three PRs close
that loop.

- **#379 `fix(llm): cap minimax max_tokens at 524288`** — pre-probe
  fix. The MiniMax-M3 model rejects anything `> 524288` with HTTP 400
  ("model[MiniMax-M3] does not support max tokens > 524288"); PR #379
  pins `MINIMAX_MAX_TOKENS_CAP = 524_288` in `src/llm/capabilities.rs:53`
  and threads the three-layer clamp (operator override → cached table
  → `MINIMAX_MAX_TOKENS_CAP`) through `src/llm/minimax.rs:295`. 4 new
  tests in `src/llm/capabilities.rs::tests`.
- **#400 `feat(llm): auto-detect max_tokens per (provider, model)
  via runtime probes`** — the headline feature. New
  `src/llm/probe.rs` (619 lines, doc-heavy) implements the two-phase
  search: 30 sequential exponential probes at `2^1..2^30` (first
  failure breaks the loop), then 20-point parallel bisect batches
  (`up_to_32_rounds`) clamped to `[MIN_AUTOPROBE_FLOOR = 1024,
  MAX_AUTOPROBE_CEILING = 2^30]`. The discovered value is persisted
  to `~/.local/share/moagan/max_tokens_auto.toml` via the new
  `src/llm/probe_table.rs` (556 lines, the in-memory `MaxTokensTable`
  + on-disk `MaxTokensTableFile`). Opt-in per
  `ProviderConfig::max_token_auto: Option<u32>` (default `Some(1024)`).
  See `docs/max-tokens-auto.md` for the rationale and the disable
  recipe (`MOAGAN_MAX_TOKEN_AUTO=false`).
- **#401 `fix(llm): send_probe bypasses every cap + zero retries;
  5xx -> Indeterminate`** — the corrective PR. The probe must bypass
  every cached cap (the cached value cannot constrain the probe that
  discovered it) and must NOT retry on 5xx (a 5xx means the probe
  budget is exhausted, not a transient failure). PR #401 introduces
  `ProbeOutcome::Indeterminate` and threads a `bypass_all_caps: true`
  flag through `send_probe`. 13 files changed, +1013 / -288 LoC.

The mock provider skips the probe and returns `DEFAULT_MAX_TOKENS =
1_000_000` (mirror of v0.5 behaviour). The `discover` / `run` modes
that flow through `ProviderRegistry` consult the cached table before
issuing each call; the precedence is **operator override → cached
table → `MINIMAX_MAX_TOKENS_CAP` / `OPENCODE_GO_MAX_TOKENS_CAP` →
wire**. ~36 new tests in total across `src/llm/probe.rs` (13),
`src/llm/probe_table.rs` (10), `src/llm/capabilities.rs::tests` (7,
of which 4 pre-date v0.7.1 from #379), and the new
`tests/integration_max_tokens_auto.rs` (296 lines, 6 tests); PR #400's
own description also lists 11 config + registry tests in
`src/llm/provider.rs` / `src/config/mod.rs` + 4 wire-body tests across
the per-provider `send()` files for ~45 total per the PR author.
PR #401 added 0 net new test functions (modifications + 3 helper
methods on `MaxTokensTable` only).

## 5. Dependency / housekeeping

### Cluster C — Dependabot action refresh (#371)

`ci(deps): refresh action SHAs + refine Dependabot groups` — the
v0.6.0 Node-24 bump (#336) had pinned actions to a specific Node-24
SHA, but several of those SHAs had been superseded. PR #371 refreshes
the pinned SHAs (`actions/checkout`, `actions/setup-node`,
`actions/cache`, `actions/upload-artifact`, `actions/download-artifact`)
to the latest published versions and refines the Dependabot groups
so the GitHub-Actions bump cycle batches into one PR per group
(`github-actions-major`, `github-actions-minor`, `cargo-runtime`,
`cargo-dev`). `.github/workflows/e2e-network.yml` and
`dependabot.yml` touched.

### Release bumps (#381, #399)

- **#381** — `chore(release): Cargo.toml 0.6.0 → 0.6.1`. The v0.6.0
  release-cargo was `0.6.0` (after the #358 rewind) but the package
  was still carrying the five PRs that did not warrant a full
  release name; #381 bumps to `0.6.1` so the published artifact
  matches the tag.
- **#399** — `chore(release): Cargo.toml 0.6.1 → 0.6.2`. Same pattern
  after the e2e-network rebuild landed. Tag `v0.6.2` (object
  `ce7e46d4`) cuts the rebuild + matrix-filter cascade + 28-min
  timeouts + proxy error capture + binary placement + cache fix.
