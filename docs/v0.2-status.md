propuestas `proposal-01-concept.md` (V4), `proposal-02-rust.md` (T01-06),
y `proposal-03-add-ons.md` (catálogo aditivo).

verificado por `cargo test` + smoke. Cuando aparece ⏳, falta trabajo.

## ✅ Implementado y verificado

### Pipeline de 10 fases (v0.1)

- `src/phases/{intake,clarify,route,propose,gate,critique,repair,judge,rank,deliver}.rs`
- `src/phases/sketch_phase.rs` (añadido en fase A)
- Modos operativos: `fast`, `standard`, `deep`, `explore`, `batch` — ver `src/cli/mod.rs::Mode`.
- `fast` salta `SketchPhase` (cardinalidad 0); el resto produce 4-12 sketches según modo.
- Salidas estándar: `final/{portfolio.md,recommendation.md,deltas.md}`.

### Persistencia (v0.1 + fase A)

- `ranking/{pareto,diversity,cluster}.rs` — frente de Pareto + diversidad por crowding distance + cluster básico (no es el clustering LLM del discovery).
- `storage/sqlite.rs` con migraciones embebidas (v001–v004). Última migración añadida: `v004_calls_body_sha256.sql` (audit-sidecar).
- `redact/{patterns,apply,writer}.rs` — redacción configurable aplicada en `RedactWriter`.
- `secret.rs::SecretString` con `Debug=***`, `Display=***`, `Drop=zeroize` (implementación manual sin `secrecy`).

### Providers y cliente HTTP (v0.1)

- `llm/mock.rs`, `llm/minimax.rs` (los dos providers productivos).
- `llm/{http,wire,wire_format,provider}.rs` — trait `Provider`, wire Anthropic, `circuit_breaker`, `rate_limiter`, `budget`.
- `llm/cache.rs` — caché cross-run por hash BLAKE3 canónico.

### Telemetry (v0.1)

- Anillos `run`, `phase`, `call` con `phases.jsonl.gz` + `calls.jsonl.gz`.
- Redacción al escribir (vía `RedactWriter`).

### Audit-sidecar (commit #6)

- `src/audit/{mod,format,proxy,verify}.rs` + `src/cli/audit.rs`.
- HTTP forwarder sobre `std::net::TcpListener` (sin `axum`/`hyper`).
- Formato JSONL con CRC32 por línea + headers saneados.
- Match por `body_sha256` (±2s) contra `calls.jsonl.gz` interno, con fallback timestamp-only.

### CLI

- Subcomandos: `run`, `continue`, `inspect`, `doctor`, `audit proxy`, `audit verify`.
- Filtros permitidos por `--no-forgen-crates` y `--no-anthropic-sdk` (en `Makefile` + `scripts/`).

## Discrepancias específicas detectadas (docs ↔ código)

1. **`proposal-02-rust.md §0.5#3`** dice que el cache en disco es `flat`. La implementación actual (`src/llm/cache.rs::path_for`) ya shardea por 4 hex chars de la mitad del hash. Es **diferente** del plan B que pidió 2-hex single-level. La sub-fase E unifica a la convención del plan B.
2. **`Cargo.toml` versión `0.1.0`**: el binario dice ser v0.1 aunque los PRs v0.2 están mergeados. Es un descuido, no un problema. Lo arreglaría un commit de mantenimiento.
3. **`Mode::Discovery`** no existe como variante — el comentario en `src/cli/mod.rs:23` dice literalmente *"deferred to a later sub-phase"*. Coincide con el plan B.
4. **No existe** `src/phases/validate.rs` pero `src/phases/gate.rs` cubre la fase 6 (gate) por completo; la fase 7 (validate) sí falta — es la pieza de sub-fase C.
5. **Tabla `calls.body_sha256`** añadida en migración v004 — sólo la consume el audit-sidecar vía `src/storage/sqlite.rs`. Los callers de la cache LLM la desconocen todavía.

## Plan de implementación por sub-fase

Orden recomendado para Plan B. Cada sub-fase es una rama `feat/mvp-v0.2-phase-{e,c,b,d}` siguiendo el patrón que ya usamos para `phase-A` y `audit-sidecar`.

| Sub-fase | Capacidad                                              | Commits estimados | Riesgo   |
|----------|--------------------------------------------------------|-------------------|----------|
| **E**    | Cache sharded (2-hex) + TTL + LRU                       | 2-3 + 1 doc       | Bajo     |
| **C**    | Validadores (Rust/Python/TS) + sandbox básico           | 5-7               | Medio    |
| **B**    | Modo discovery completo (matriz → integradas)          | 12-18             | Alto     |
| **D**    | Síntesis intra-cluster + adversary + checkpoints stdlib | 4-6               | Medio    |

Cada sub-fase cierra con validación del usuario antes de empujar y abrir
PR (pasos 4-10 del protocolo).

## Conventions del repo (recordatorio)

- Un commit lógico por cambio.
- Commits firmados con GPG (clave `414687A3CD7E65B9`).
- Antes de cada commit:
  ```bash
  cargo fmt --all -- --check
  cargo clippy --all-targets -- -D warnings
  cargo test --all-targets
  cargo build
  ```
- Smoke gates:
  - `moagan run --mode fast --provider mock` produce `final/portfolio.md` + `rankings/ranking.json`.
  - `moagan run --mode fast --provider minimax` con `MINIMAX_API_KEY` produce los mismos artefactos y escribe `telemetry/calls.jsonl.gz`.
- No-go list aplicada vía `scripts/check-no-forbidden-crates.sh` + `scripts/check-no-anthropic-sdk.sh`.
