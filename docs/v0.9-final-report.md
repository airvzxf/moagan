## 3. Categorías de cambios

### 3.1 — Telemetry push-side wiring (#508)

`fix(telemetry): wire SaturationSink into BreakeredProvider at
registry time`. Follow-up to #494 (v0.8). The push-side
`SaturationSink` on `BreakeredProvider` (catalog §D.23 + §D.27)
was reachable only through the consuming builder on individual
wrappers; `registry_from_config` / `insert` / `with_pool` all left
it at `None`, so circuit-open and rate-limit rejections on the
production LLM call path landed in memory only —
`telemetry/saturation.jsonl` and the `saturation_events` SQLite
mirror stayed empty in real runs.

- Move the sink to a per-instance
  `parking_lot::Mutex<Option<Arc<dyn Sink>>>` on
  `BreakeredProvider` (per-instance cache, not app-wide state —
  keeps the no-go list satisfied).
- Add a parallel `HashMap<String, Arc<BreakeredProvider>>` of
  downcast handles to `ProviderRegistry`.
- Expose `with_saturation_sink` / `attach_saturation_sink` /
  `registry_from_config_with_sink` /
  `with_home_and_sink` so the CLI pipeline can wire `Telemetry`
  as the sink right after `Telemetry::open`.
- `Telemetry` already implements `SaturationSink` (re-stamping
  the event with the current `run_id`), so the JSONL stream and
  SQLite mirror stay in lock-step with no extra plumbing.
- Two new integration tests pin the contract end-to-end:
  `registry_attach_saturation_sink_routes_to_telemetry` and
  `registry_from_config_with_sink_attaches_sink_at_construction`.

### 3.2 — ProcessLease API tipada (#506)

`feat(storage): typed ProcessLease API with FencingToken +
heartbeats (D.1.5)`. Closes the long-deferred D.1.5 item. The
legacy `Db::acquire_process_lock` / `Db::release_process_lock`
scaffolding is replaced by a typed `ProcessLease` API that
allocates a monotonic `FencingToken` via SQL `MAX(fence) + 1` and
validates it on heartbeat / release.

- **`FencingToken`**: monotonic SQL-allocated token prevents
  stale-holders from releasing a lock they no longer own.
- **`heartbeat_process_lock`**: bumps `last_heartbeat_unix`
  without extending the fixed `expires_at_unix` abandon
  deadline.
- **Schema migration `v019`**:
  `process_locks` `ADD COLUMN last_heartbeat_unix INTEGER NOT
  NULL DEFAULT 0`. Purely additive — the existing
  `fence` / `acquired_at_unix` / `expires_at_unix` columns keep
  their role.
- **`LeaseGuard` is NOT touched**: it keeps its existing typed
  API and continues to share the `process_locks` table with
  the new `ProcessLease` (different keying — `LeaseGuard` is
  per-run / single-holder, `ProcessLease` is per-holder /
  fence-protected).
- 5 new unit tests + 1 new integration test
  `process_lease_lifecycle_acquire_heartbeat_release`.

### 3.3 — HardIncompat catalog extensions (#504)

`feat(domain): extend HardIncompat enum with 3 opt-in catalog
variants`. Adds three new variants to the `HardIncompat` enum
documented in `docs/proposal-03-add-ons.md` §D.13.15:

- **`ClusterLocalInGlobal`**: forbids `cluster_local`-scoped
  resources from being deployed at a `global` scope.
- **`PullInPushOnly`**: forbids pull-mode adapters in push-only
  topologies.
- **`StatelessInStateful`**: forbids stateless components inside
  a stateful topology that requires session affinity.

Follows the same "typed records without detector wired-in"
pattern as the 6 opt-in variants already shipped in §D.13.15:
enum + `explain()` + serde round-trip + catalog loader. The
detector layer is intentionally left for a follow-up — this
PR ships the typed contract only. 4 new unit tests + extended
count assertion; one regression test pins the contract that
opt-in variants do **not** fire on canonical pairs (preserves
default-detector behavior).

### 3.4 — AsyncEmbedder trait (#512)

`feat(embed): AsyncEmbedder trait + sync bridge for RemoteEmbedder`.
Closes the B#18 follow-up from #496 (v0.8). Adds a new
`AsyncEmbedder` trait (`async embed_batch` + `dim` + `name`) as
the canonical fallible, batch-friendly surface for network-backed
embedding adapters.

- **`AsyncEmbedder` trait**: canonical async surface for
  network-backed embedding adapters.
- **`Embedder` sync impl for `RemoteEmbedder`**: via
  `tokio::task::block_in_place` + `tokio::runtime::Handle::block_on`,
  with a cache short-circuit identical in shape to
  `HashingEmbedder`.
- **`cluster_by_embedder` stays sync**: the clusterer can drop
  in `RemoteEmbedder` in place of `HashingEmbedder` without
  code changes.
- **Multi-thread-runtime requirement**: prominently flagged in
  `Embedder`'s mod-level doc comment (production satisfies it
  via `Builder::new_multi_thread` in
  `src/lib.rs::run_blocking`).
- Rename the inherent `RemoteEmbedder::embed_batch` to the
  private `embed_batch_transport`; the public async surface
  is `AsyncEmbedder::embed_batch`. 6 new tests pin the
  contract end-to-end.

### 3.5 — proptest dev-deps + hotfix (#510, #514)

`test(proptest): property-based tests for critical hashes`
(#510) introduces `proptest = "1.4"` exclusively under
`[dev-dependencies]` (verified with `cargo tree --release` — no
proptest in the release binary). Release-build cleanliness is
enforced by `scripts/check-no-forbidden-crates.sh`, which
rejects a `[dependencies]` row and is wired into the lefthook
pre-commit guard.

- **30 new tests** (24 proptest blocks × ~256 generated inputs
  each) covering 5 hash-heavy files:
  - `src/ids.rs` — BLAKE3 / SHA-256 / `canonical_hash`
    determinism + separator-safety, RunId uniqueness + format
    stability, UUID wire-form round-trip.
  - `src/llm/cache/mod.rs` — `Cache::cache_key` discrimination
    across every identity field (system, user, max_tokens,
    temperature, top_p, provider, model) plus the deterministic
    hex shape of the output digest.
  - `src/llm/wire.rs` — `build_cache_key` invariants for both
    Blake3 and Sha256 algorithms, including the
    `extra_messages` invariant that keeps the PromptPrefill
    retry from invalidating the steady-state cache.
  - `src/llm/rate_limiter.rs` — bucket capacity ceiling under
    refund storms, `try_acquire` accounting vs bucket
    arithmetic, capacity / refill_per_sec round-trip.
  - `src/storage/compression.rs` — gzip + zstd byte-exact
    round-trip for arbitrary payloads, multi-member stream
    recovery, `Compression::from_extension` classifier
    determinism.
- Adopt the `name in <strategy>` syntax (rather than
  `pattern: type`) for readability and to mirror the upstream
  proptest 1.4 idioms.
- `proptest-regressions/` added to `.gitignore` so the scratch
  directory proptest writes on failed property runs stays
  machine-local.

**Hotfix #514**: `fix(test): add missing prop_assume in cache_key
proptest`. The `prop_cache_key_distinguishes_provider_and_model`
test was missing the `prop_assume!(model != other_model)` clause,
allowing proptest to degenerate to inputs where
`model == other_model`, making the second assertion
(`key_m1 != key_m2`) trivially false. 1-line fix in
`src/llm/cache/mod.rs:931`.

  upgrade.

  > 100 MB binary). Deferred to v0.10+ by cost.

  added in #504. The typed records ship; the detector layer is
  intentionally left for a follow-up.
- **CLI wire-up of `maybe_run_via_dag`** when
  `mode == "deep"`. The dispatcher is gated and ready
  (`#520`); `cli/run.rs::build_pipeline_for_mode` is the
  natural call site (~5-line change).
- **K.4 wire-up of `fetcher::fetch_one`** for routing PDFs to
  the new `src/research/pdf.rs::fetch_pdf_text` parser.
  The parser ships; the fetcher dispatch is the follow-up.
- **`process_locks` heartbeat sweep / GC**. The lease module
  ships; a periodic sweeper that releases abandoned leases
  based on `expires_at_unix` is the natural follow-up.

  - Absorbs: PRs #504, #506, #508, #510, #512, #514, #516,
    #518, #520 (the 9 substantive feature PRs).
  - The meta-documentation PR (#502) is referenced in §4.1
    but is part of the same release window.

The v0.8.0 → v0.9.0 cycle is linear: the tag absorbs the
cumulative PR set and the post-merge state of `main` matches
the tag target (no post-tag housekeeping, except for the
follow-up PR that fills in `tag_object` in the front matter —
the same pattern as v0.8.0 / PR #501).

## 9. Quick-start for the next maintainer

To reproduce the v0.9.0 artifact:

```bash
git checkout v0.9.0
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.9.0
```

To reproduce with the optional DAG backend enabled:

```bash
git checkout v0.9.0
cargo build --release --locked --features dag
./target/release/moagan --version   # → moagan 0.9.0 (dag)
```

The GitHub Release page
(https://github.com/airvzxf/moagan/releases/tag/v0.9.0)
hosts the published binary plus `sha256`, `sha512`, and the
CycloneDX SBOM (`moagan.sbom.cdx.json`).

To reproduce the v0.8.0 → v0.9.0 chain (for diff review):

```bash
git checkout v0.8.0
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.8.0
git checkout v0.9.0
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.9.0
```

The K.4 PDF fetcher requires `poppler-utils` installed
on the host:

```bash
pacman -S poppler          # Arch
apt install poppler-utils  # Debian/Ubuntu
```

When the binary is missing, the fetcher returns
`Error::ResearchUnavailable` with an explicit install hint —
no silent failure.
