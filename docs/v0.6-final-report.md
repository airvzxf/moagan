## 3. Per-cluster sub-summary

### Cluster A — CI gauntlet (#334, #336, #338)

Restores the nightly `cargo-audit` workflow to a green state after
`cargo-audit 0.21` removed `--no-dev`, brings every GitHub Actions
workflow and the `rust-setup` composite into the Node-24 runtime
(matching the deprecation that landed on 2025-09-19), and restructures
the single-job `e2e-network.yml` into a 3-row `strategy.matrix`
(`card80` / `fast` / `explore`) so the ~35-minute real-LLM suite no
longer kills the runner on every push to `main`. Each new matrix row
keeps the pre-existing `SKIP: real proxy e2e (MINIMAX_API_KEY not
present)` honoured, so the no-key dev path is preserved. Dependabot was
tightened from `weekly / monday / 3-PR cap` to `daily / 5-PR cap` so
the next bump cycle does not pile up again.

### Cluster B — CLI/config (#340, #342)

Wires the four CLI flags that had been parsed-and-dropped by clap:
`moagan run --no-replace-sources`, `moagan rerun --same-config` (with
explicit `--same-config=false` parser support), `moagan repair --run
<RUN_ID>` (scopes `cleanup_orphans` / `reindex_artifacts` /
`recover_zombies` to the target run), and `moagan run --max-parallelism`
(cap-validated at both `run` and `discover` entry points). 13 new
colocated tests.

Re-writes the config-file precedence from layered-merge to
**strict cwd-overrides-user**: `MOAGAN_CONFIG` →
`./moagan.toml` or `./.moagan.toml` → `${XDG_CONFIG_HOME}/moagan/config.toml`
→ defaults. The cwd file shadows XDG completely — no merge, no surprise
overrides. Adds `api_keys.toml` resolution as a first-class lookup
helper (`src/llm/api_keys.rs`), makes `ProviderConfig::temperature`
and `top_p` actually used by `call_with_retry` / `call_uncached`
(prior art: the fields parsed but were never read), and extends
`moagan doctor` to check every keyed provider (`minimax`, `deepseek`,
`opencode_go`) via the unified helper rather than only `MINIMAX_API_KEY`.
17 new tests across `src/llm/api_keys.rs`, `src/config/mod.rs`,
`src/phases/phase.rs`, `src/cli/doctor.rs`.

### Cluster C — JSON robustness pipeline (#344, #346, #348, #350, #352, #354)

Six PRs that, taken together, replace the v0.5 single-pass bracket
repair + response-only extract with a layered recovery chain that
handles the failure modes the operator run surfaced (see §4):

- **Iterative bracket repair** (#344): `repair_brackets_iterative`
  loops the single-pass walker up to 3 times, emitting one
  `RepairEvent::Bracket` per pass so the trace stream mirrors the
  work done. Preserves the pre-iterative chain's contract — after
  `max_iters` without a parse success, the function returns the last
  repaired candidate so the caller's `Error::SchemaViolation` path
  still surfaces with the per-pass events.
- **Chat-template token strip** (#346): strips ChatML markers
  (`<|im_start|>`, `<|im_end|>`, `<|eot_id|>`, `<|end_of_turn|>`,
  `<|endoftext|>`), section markers (`<system>`, `<assistant>`, etc.),
  and bracket tokens (`[BOS]`, `[EOS]`, plus typo-tolerance for
  `[BO S]` / `[EOS ]`) on the JSON response path. Wired into
  `phases::util::parse_model_json_traced` rather than
  `json_extractor::extract_tolerant_json` (offset-alignment reason
  documented in the PR body). The ASCII control-byte strip
  (`control_tokens::strip`) was previously only wired on intake +
  SSE; this PR brings it onto the JSON response path too.
- **opencode_go response_format capability/contract drift** (#348):
  `Capabilities::for_opencode_go_responses` advertised
  `supports_response_format: true` but the wire body never serialised
  the field. PR #348 threads the same gate the OpenAI-compat path
  uses into `encode_body` / `build_responses_body`. The
  `model_skips_response_format` opt-out list still wins for the six
  stubborn models.
- **`STUBBORN_MODEL_JSON_PREFIX`** (#350): prepends a strong
  "CRITICAL OUTPUT CONTRACT" prefix to the role's system prompt for
  the six opt-out models (`glm-5.1`, `glm-5.2`, `kimi-k2.6`,
  `kimi-k2.7-code`, `kimi-k3`, `deepseek-v4-pro`). Non-opt-out models
  receive the role's prompt byte-for-byte. The constant is
  `pub const STUBBORN_MODEL_JSON_PREFIX: &str` and the helper
  `render_system_prompt_with_prefix(role, model, base_prompt)` is
  wired into both `call_with_retry` and `call_uncached` so cache
  hits, cache misses, and parse-failure retries all see the same
  reinforced prompt.
- **JsonRepairV2 default-on for discovery** (#352): `discover` mode
  now flips `json_repair_v2_enabled` ON unconditionally; every other
  mode still honours the explicit opt-in (`llm.json_repair_v2_enabled`
  in `config.toml` or `MOAGAN_JSON_REPAIR_V2_ENABLED=true`). The
  decision matrix is implemented in
  `Config::json_repair_v2_enabled_for_mode(mode)` — the single source
  of truth. The pre-existing 3 `json_repair_v2_*` tests use
  `mode="standard"` with the typed config flag and continue to pass.
- **Focused continuation on truncation** (#354): a 5-step loop
  inserted at `phases::phase::call_with_retry_parse` that captures
  the last 500 chars of a truncated response, re-calls the same
  provider/model with `Role::Continuation` and
  `prompts/continuation.md`, concatenates the continuation's
  `continued` field, and re-runs the parse chain. Capped at 2
  continuation attempts per call; `truncated = 1` becomes permanent
  after the second failure. Each attempt emits a
  `model.continuation_attempt` telemetry event. The continuation
  call deliberately bypasses `call_uncached` and goes through
  `dispatch_to_provider` with a hand-built `Request` so the
  stubborn-model JSON prefix is NOT prepended — the continuation
  prompt IS the contract.

### Cluster D — per-provider temperature matrix (#356)

`src/discovery/matrix.rs` gains a `TemperatureProfile` struct plus
per-provider `temperature_profiles` and `default_profile` fields on
`ExplorationMatrix`. CLI surface: `--temperature-profile
'provider=<model>;temperatures=<csv>;replicas=<n>'` (last-wins on
duplicates for the same provider). TOML surface:

```toml
[discovery_matrix]

[discovery_matrix.temperature_profiles."minimax-m3"]
temperatures = [0.0, 0.3, 0.7, 1.0]
replicas_per_temperature = 4
```

The default profile (`[1.0] × 1`) reproduces the v0.5 single-shot
contract byte-for-byte so unconfigured runs see no behavioural change.
Cardinality formula:

```
fan_out = dimensions × facets × sketches_per_cell ×
          (Σ_per_provider |temperatures| × replicas)
```

Resolves the `roles × models × temperatures` spec drift documented in
`proposal-03 §D.13.19` (the v0.5 PR-16 marker). 16 new tests across
`discovery::matrix`, `cli::discover`, `phases::phase::tests`,
`discovery::coordinator::tests`, `config::tests`.

### Per-model JSON recovery strategy (standalone feat, #360)

Adds `JsonRecoveryStrategy { Strict, Lenient, Continuation, PromptPrefill }`
and a per-model default table that maps each known stubborn model
onto one of the four strategies:

| Model | Strategy |
|---|---|
| `kimi-*` | `Lenient` |
| `glm-*` | `Lenient` |
| `hy3`, `mimo-*` | `Lenient` |
| `deepseek-v4-pro` | `PromptPrefill` |
| `deepseek-v4-flash` | `PromptPrefill` |
| `minimax-*` | `Continuation` |
| `gpt-5.6-luna` | `Strict` |
| (default) | `Lenient` |

`parse_with_strategy` parameterises the parse chain so each strategy
selects the right subset of (iterative brackets + chat-template strip +
tolerant extractor + bounded continuation + assistant prefill). The
OpenAI-compat body builder gains assistant-prefill support for
`PromptPrefill` (test fixtures in `llm/wire.rs` updated for the new
`Request::extra_messages` field). 39 new tests across
`src/llm/json_strategy.rs` (20), `src/llm/json_extractor.rs` (9),
`src/llm/openai_compat.rs` (3), `src/llm/wire.rs` (3),
`src/phases/phase.rs` (4).

### Release housekeeping (#358, #362, #364, #365, #367, #368)

- **#358** — `chore(release): Cargo.toml 0.6.1 → 0.6.0`. The PR #330
  bump had eagerly landed `0.6.1` while the next release name was
  always **v0.6.0**. PR #358 rewinds the manifest to `0.6.0` so the
  tag and the version string line up. No source or API changes.
  Manifest-only.
- **#362** — `fix(release): download SBOM artifact before bundle step`.
  `anchore/sbom-action@v0.18.0` (Node-24 bump in #336) no longer
  writes the SBOM to the workspace; it only uploads it as a separate
  artifact. PR #362 inserts an `actions/download-artifact@v5` step
  between the SBOM generation and the Bundle step so the SBOM file
  lands at `${{ github.workspace }}/moagan.sbom.cdx.json` where
  Bundle expects it. One yaml hunk, +15 lines.
- **#364** — `fix(llm): cap opencode_go max_tokens at 16_384`. The
  upstream rejects anything `>393216` with HTTP 400; the discovery run
  hit this with `kimi-k2.7-code` (documented in
  `/tmp/discover-json-fix-report.md:65`). Three-layer defence:
  `OPENCODE_GO_MAX_TOKENS_CAP = 16_384` constant in
  `src/llm/capabilities.rs`, per-wire-body clamp in the three
  OpenCode Go providers, and `default_providers()` now sets
  `max_tokens: Some(OPENCODE_GO_MAX_TOKENS_CAP)` for every
  `make_opencode_go(...)` entry (down from `Some(DEFAULT_MAX_TOKENS)`).
  8 new tests.
- **#365** — `docs: update CLI cheatsheet for v0.6.0 surface`. Brings
  `docs/cli-cheatsheet.md` in sync with the v0.6.0 CLI; documents
  `--temperature-profile` (PR #356), `--same-config` and `--no-replace-sources`
  (PR #340), the strict cwd-overrides-user config precedence
  (PR #342), the `blake3` default for `--hash-algo`, and the
  opencode_go `max_tokens` hard-cap (PR #364). Behaviour
  correction: `moagan continue --from-pause` + `--kind discovery`
  is NOT a clap conflict — the pause branch short-circuits at
  `src/cli/mod.rs:1016-1024` and silently ignores `--kind`.
- **#367** — `feat(telemetry): add 'moagan telemetry plan' subcommand
  for quota view`. Aggregates the per-call `calls` table over a
  rolling window (default 7 days), grouped by `(provider, model)`,
  with optional `used / limit (P%)` when the provider has a
  `[providers.X].plan = { plan_id, limit_tokens, window_days }` block
  configured. 9 new tests; 13 files touched.
- **#368** — `docs(proposal-03): mark v0.6.0 add-ons as resolved`.
  Marks `D.13.19` (per-provider temperature matrix → PR #356),
  `D.15.1` (Config::load strict cwd-overrides-user + api_keys.toml
  wiring → PR #342) and `D.19.3` (telemetry plan quota view →
  PR #367) as **Implementación v0.6.0**. Doc-only PR; 24 insertions,

## 4. Discovery operational

Before closing the v0.6.0 cluster, the user requested an end-to-end
operational discovery run to test the JSON robustness pipeline against
real LLM failure modes. The run was performed against three providers
with the user's per-provider temperature profile, `JsonRepairV2`
default-on (discovery mode), and the stubborn-model prompt prefix
applied:

- **minimax-m3** (via local audit proxy → `https://api.minimax.io/anthropic/v1`).
  Killed at 8 min on the first partial, killed again on the second — the
  upstream serialises requests (14–48 s wall-clock per call, no
  observable concurrency even with `--max-parallelism=24`). 13 matrix
  sketches combined across both partials; HCC depth 5–8.
- **opencode_go** (`kimi-k2.7-code`, in `DEFAULT_OPT_OUT`).
  41 min, killed mid-matrix once cardinality hit 80. 82 matrix + 6
  pre-matrix = 88 total sketches. PR-C6 verified: `kimi-k2.7-code` is
  in the static `DEFAULT_OPT_OUT` list, so the system prompt
  auto-prepends `STUBBORN_MODEL_JSON_PREFIX`. HCC depth 4–6.
- **deepseek-v4-flash** (opencode_go → `https://opencode.ai/zen/go/v1`).
  17 min, completed end-to-end including post-matrix. 40 matrix + 6
  pre-matrix = 46 total sketches. 149 LLM calls. Re-confirmed the
  opencode_go `max_tokens` > 393216 → HTTP 400 issue (fixed in
  PR #364).

Top hypothesis shipped as **PR #360** (per-model JSON recovery
strategy enum). The remaining hypotheses from the report — `#2
normalize_to_value`, `#3 opening-brace prefill` — are partially
addressed by PR #360's `PromptPrefill` strategy (which is the
"opening-brace prefill" idea) and otherwise deferred to v0.6+ /
v0.7. The full report is saved at
`/tmp/discover-json-fix-report.md` (139 lines).

**Operational gotcha worth carrying into the v0.6+ workflow**:
the opencode_go upstream rejects `max_tokens > 393216` with HTTP 400.
Documented at `/tmp/discover-json-fix-report.md:65`; fixed in
PR #364 as the three-layer defence described in §3.

## 5. Deferred to v0.6+ / v0.7

The following D.x catalogue items and infra upgrades are intentionally
deferred — recorded here so future readers do not mistaken them for
shipped work:

  runtime `SaturationEvent` triggers, cross-run `csv` aggregation).
  PR #367 ships the read-only `moagan telemetry plan` view; the
  push-side alerting + live dashboards are still deferred.
- **D.29-D.32** retención cross-run cleanup. The `safe_path` helper
  (PR #306 from v0.5) covers the local path-hygiene side; the
  cross-run retention sweep is not yet implemented.
- **`petgraph`** for the optional DAG backend. The phases pipeline
  still uses the linear `phases/` vector + `canonical_phase_order`.
- **`comfy-table`** for the CLI table outputs. `moagan inspect`,
  `moagan telemetry provider`, and `moagan telemetry plan` use plain
  text today.
- **`proptest`** for property-based testing. The current test suite
  is hand-rolled (`#[test]` cases).
- **`RemoteEmbedder`** adapter. Only `HashingEmbedder` ships today.
- **v0.6+ multimodal streaming** if/when upstream providers support
  it.
