## 3. Categorías de cambios

### 3.1 — K.4 fetcher PDF routing (#527, fetcher slice)

`feat(v0.10): K.4 fetcher PDF routing` (slice of #527). The
K.4 sub-1 PDF parser shipped in #518
(`src/research/pdf.rs::fetch_pdf_text`) was orphaned — no
caller in the dispatch path. `ResearchFetcher::fetch_one`
previously passed every URL through the HTML branch
unconditionally; the new code detects URLs ending in `.pdf`
via `pdf::looks_like_pdf_url` and routes them to the PDF
parser **after** the allowlist gate. The allowlist gate is
preserved as the first defense — a `.pdf` URL on a malicious
host is rejected as `DisallowedHost` before any socket is
opened, so the new dispatch never widens the attack surface.

- Route detection: `ends_with(".pdf")` (case-insensitive
  ASCII-only); `looks_like_pdf_url` mirrors the `fetch_pdf_text`
  helper's own URL classification to keep `fetcher` and
  `pdf` modules consistent.
- Host gate ordering preserved: allowlist check first, then
  PDF routing decision, then parser call. A `.pdf` URL on
  an allowed host routes to `fetch_pdf_text`; a `.pdf` URL on
  a disallowed host raises `Error::ResearchUnavailable` with
  the `DisallowedHost` reason code.
- HTML URLs continue through the existing path unchanged.
- 3 new unit tests pin the contract:
  `fetch_one_routes_pdf_url_to_pdf_parser`,
  `fetch_one_preserves_html_path_for_non_pdf_url`,
  `fetch_one_rejects_disallowed_pdf_host_before_parse`.

Files: `src/research/fetcher.rs` (+171 LoC). No new
dependencies. No schema changes. The `poppler-utils`
install requirement (already documented for #518 in
`docs/v0.9-final-report.md §3.7`) carries forward.

### 3.2 — HardIncompat detector wiring (#527, constraint + synthesize slices)

`feat(v0.10): K.4 fetcher PDF routing + HardIncompat detector
wiring` (the constraint + synthesize slices of #527). Three
opt-in catalog I.6 variants existed as typed records since
#504 (`ClusterLocalInGlobal`, `PullInPushOnly`,
`StatelessInStateful`) but had no detection logic. #527 wires
them:

- **`src/domain/constraint.rs`** (+259 LoC):
  - `detect_cluster_local_in_global(plan) -> Vec<HardIncompat>` —
    fires when a `Plan` declares a `cluster_local`-scoped
    resource with a `global` deployment scope. Fires on a
    single canonical pair; does not fire on `cluster_local` +
    `cluster_local` or on `global` + `global`.
  - `detect_pull_in_push_only(plan) -> Vec<HardIncompat>` —
    fires when the topology is `push_only` and any adapter
    declares mode `pull`. Fires on the canonical
    `(push_only, pull)` pair; does not fire on
    `(push_only, push)` or `(pull, pull)`.
  - `detect_stateless_in_stateful(plan) -> Vec<HardIncompat>` —
    fires when the topology requires session affinity
    (`stateful_session`) and any component declares
    `lifecycle = stateless`.
  - `cluster_opt_in_hardincompat(plan, base_detector) ->
    (Vec<HardIncompat>, Vec<HardIncompat>)` —
    deterministic-order wrapper: returns `(fatal,
    skipped_opt_in)` with stable ordering on the 3
    opt-in variants (alphabetical by variant name) to keep
    the sidecar writer's output stable.

- **`src/phases/synthesize.rs`** (+297 LoC):
  - `SynthesizePhase` now invokes the base detector first,
    then the opt-in wrapper, before passing proposals to the
    jurado.
  - Adds a `skipped_opt_in` sidecar sink that writes
    `jsonl` records next to the existing `skipped` stream
    (`final/skipped_opt_in.jsonl`) so the 3 opt-in variants
    are visible without changing the existing
    `final/skipped.jsonl` schema.
  - The wrapper respects the matrix-path precedence rule:
    when both the matrix path and the catalog-skip path
    detect the same component, the matrix path wins.

- 7 unit tests in `src/domain/constraint.rs` (3
  fires-on-pair, 3 does-not-fire, 1 deterministic-order
  wrapper).
- 3 integration tests in `src/phases/synthesize.rs`
  covering the end-to-end path:
  `cluster_opt_in_hardincompat_filters_end_to_end`,
  `clean_cluster_does_not_emit_skipped_opt_in`,
  `matrix_path_takes_precedence_over_catalog_skip`.

Files: `src/domain/constraint.rs` (+259 LoC),
`src/phases/synthesize.rs` (+297 LoC). No new dependencies. No
schema changes.

### 3.3 — CI restructure + cache cleanup (#525)

`ci(workflows): restructure ci.yml + cache cleanup + bump
timeouts`. Two operational pain points collapsed:

- **`ci.yml`** (`/.github/workflows/ci.yml`): removed 4 jobs
  (`preflight-deepseek`, `preflight-opencode_go`,
  `test-ignored-deepseek`, `test-ignored-opencode-go`); kept
  `test-ignored-minimax` with timeout bumped 25 → 60 min.
  The removed jobs move to post-merge informative workflows
  so failures on `main` are still observable without gating
  PRs.
- **`.github/workflows/test-ignored-deepseek.yml`**: new
  post-merge informative workflow with timeout 120 min.
  Runs DeepSeek per-run tests against `main` after merge
  so regressions show up in the post-merge badge without
  blocking PRs.
- **`.github/workflows/test-ignored-opencode-go.yml`**: new
  post-merge informative workflow with timeout 120 min.
  Same rationale as DeepSeek.
- **`.github/actions/rust-setup/action.yml`**: added
  `lookup-only: ${{ github.event_name == 'pull_request' }}`
  to the `Swatinem/rust-cache@v2.9.2` step. PRs now reuse
  `main`'s cache without creating new
  `refs/pull/N/merge` entries (pollution was the dominant
  cause of the cache step running cold on PRs).
- **`e2e-network.yml`**: bumped 5 timeouts:
  - `test-card80`: 55 → 120 min.
  - `test-explore`: 28 → 120 min.
  - `test-discover-opencode-go`: 35 → 120 min.
  - `discover-opencode-go`: 45 → 120 min.
  - `test-discover-opencode-go-models`: 90 → 360 min.

No source changes; no test changes. CI infrastructure only.

### 3.4 — DeepSeek stub + retry loop (#529)

`ci(workflows): disable test-ignored-deepseek + retry loop
for fast/explore`. Two follow-ups on the CI surface:

- **`.github/workflows/test-ignored-deepseek.yml`**: replaced
  by a 38-line DISABLED stub (preserves `on:` triggers but
  emits no work). The DeepSeek pay-as-you-go budget remains
  exhausted per
  `docs/pending-items-2026-08-13.md §9.3`. The original
  workflow content is preserved as a YAML comment block at
  the top of the stub so it can be reinstated when budget
  allows with `git revert` on the stub commit.
- **`e2e-network.yml`** for `test-fast` and `test-explore`:
  each step wraps
  `make e2e-network-{fast,explore}` in a bash loop with up
  to 4 attempts (1 initial + 3 retries) and 60 s backoff
  between failures. Wall-clock per attempt is measured; if
  all 4 attempts fail, the step exits with `rc=1` so the
  job still surfaces the failure.

No source changes; no test changes. CI infrastructure only.

```bash
git checkout v0.9.1
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.9.1
```

```bash
git checkout v0.9.1
cargo build --release --locked --features dag
./target/release/moagan --version   # → moagan 0.9.1 (dag)
```

(https://github.com/airvzxf/moagan/releases/tag/v0.9.1)
hosts the published binary plus `sha256`, `sha512`, and the
CycloneDX SBOM (`moagan.sbom.cdx.json`).

To reproduce the v0.9.0 → v0.9.1 chain (for diff review):

```bash
git checkout v0.9.0
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.9.0
git checkout v0.9.1
cargo build --release --locked
./target/release/moagan --version   # → moagan 0.9.1
```

The K.4 PDF fetcher (now wired-in in v0.9.1 #527) requires
`poppler-utils` installed on the host:

```bash
pacman -S poppler          # Arch
apt install poppler-utils  # Debian/Ubuntu
```

`Error::ResearchUnavailable` with an explicit install hint —
no silent failure.
