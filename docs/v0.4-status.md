### Capacidad

- **Trigger ladder (V4 §5.3)**: `should_decompose(brief) == true`
  cuando hay ≥3 constraints, ≥3 deliverables, o magic words
  (`subproblem`, `phase`, `depends on`, `after`, `once`).
  La 5ª condición de V4 §5.3 («mix arquitectura + dominio +
  implementación») queda como follow-up del catálogo aditivo:
  requeriría añadir un campo `domain_tags: Vec<String>` a
  `Brief` y bumpear `schema_version`. Hoy los otros 3 triggers
  cubren el mismo espacio problemático desde otro ángulo.
- **Trivial path**: cuando la ladder falla, la fase escribe
  `ProblemGraph::trivial(...)` a `problem_graph.json` SIN
  gastar una llamada LLM. Tarda 0 tokens y 0 ms.
- **DAG generation**: cuando la ladder pasa, la fase llama al
  rol `decomposer` (T=0.3, top_p=0.9, max_tokens=4096) y
  parsea la respuesta como `ProblemGraph`.
- **DAG repair**: la fase valida el grafo con Kahn; un grafo
  con ciclos o dependencias colgantes se repara eliminando
  nodos ofensivos. Si todo se cae, vuelve al trivial path.
- **Sketch DAG distribution**: `SketchPhase` consume
  `problem_graph.json` cuando existe y es no-trivial. Las
  sketches se distribuyen por nodo (1 sketch por nodo o
  `ceil(count / node_count)` por nodo).
- **SQLite mirror**: la tabla `problem_graphs` (migración v006)
  registra `(run_id, brief_blake3, should_decompose, node_count,
  at_unix)` por run. Permite queries estilo `moagan inspect`
  del tipo «qué runs hicieron decompose y cuántos nodos?».
- **Wiring**: `DecomposePhase` se inserta entre `RoutePhase` y
  `SketchPhase` SOLO en `Mode::Deep`. El resto de modos no
  insertan la fase y pagan 0 overhead.

### Métricas

- **LLM calls adicionales**: 1 por deep run (la llamada al
  `decomposer`). Se omite cuando la ladder corta.
- **Test coverage**: 9 unit tests + 8 integration tests + 17

- **Compat**: la migración v006 es aditiva. DBs pre-v006
  toleran el nuevo código vía `record_problem_graph` que

### Capacidad

**`moagan telemetry <sub>`** — los ocho subcomandos
expuestos como `Cmd::Telemetry` con dispatcher `async`
(`view::run` es la única `async`; el resto son síncronos):

- `list [--limit <N>] [--run <id>]` — tabla compacta de runs
  recientes o drill-in a uno con resumen + phases +
  provider_usage. Modo multi-run ordena por
  `created_unix DESC`.
- `summary --run <id>` — duración wall-clock + counters
  (calls, tokens, providers, phases, warnings,
  checkpoints, disk size) + secciones `by model` /
  `by phase`.
- `compare --run-a <A> --run-b <B>` — side-by-side +
  delta por métrica (`tokens`, `calls`, `ok_calls`,
  `error_calls`, `timeout_calls`, `cancelled_calls`,
  `providers`, `phases`, `warnings`, `checkpoints`,
  `duration_secs`).
- `provider [--list | --plan <name>]` — roster de
  proveedores con usage acumulado o drill-in a un plan
  (endpoint + recent usage por modelo).
- `view --port <port>` — servidor HTTP read-only sobre
  `tokio::net::TcpListener` puro (sin `axum` / `hyper` /
  `tiny_http`). Endpoints:
    - `GET /api/runs`
    - `GET /api/runs/<id>`
    - `GET /api/runs/<id>/phases`
    - `GET /api/runs/<id>/calls`
    - `GET /api/runs/<id>/provider_usage`
    - `GET /api/runs/<id>/hashes`
    - `GET /api/runs/<id>/export?level=…&format=…`
    - `GET /` (landing page)
  Loopback-only (V4 §8.8). Default port 4096;
  `pick_port` skips the blacklist `[22, 80, 443, 3306,
  5432, 6379, 8080, 8443]` and falls forward up to 1000.
  Per-request IO timeout 30s; `Connection: close` so the
  server tears down cleanly.
- `export --run <id> [--level summary|full] [--format
  tar.gz|tar|zip] [--out <path>]` — bundle el run en un
  archivo con `SHA256SUMS` canónico (formato GNU
  `sha256sum -b`). Compression `gz` para tar.gz; `deflate`
  para zip. Re-export usa `tar`/`flate2`/`zip` crates
  (ya en deps). Hash streaming con buffer 64 KiB.
- `verify --path <archive|dir>` — extrae el archivo (si es
  necesario) y re-hashea cada archivo listado en
  `SHA256SUMS`. Verdicts: `OK`, `MISSING`, `MISMATCH`.
  Devuelve `Error::InvalidState` cuando hay al menos un
  fallo (sirve como gate de CI).
- `cleanup [--dry-run]` — retention pass sobre `.runs/`.
  Tres filtros componibles (age, count, storage) +
  política `delete` o `archive`. Lee `Config::retention`
  para los knobs (`keep_runs_days: 30`,
  `keep_runs_count: 100`, `max_storage_bytes: 50 GB`,
  `policy: delete`). `--dry-run` no toca el filesystem;
  sin el flag, ejecuta la política seleccionada.

### Capacidad

**`moagan run --context <ref> [--context-summary | --context-full]`**

- `ContextRef { RunId(RunId), FilePath(PathBuf), DirPath(PathBuf) }`
  clasifica el input: UUID v7 primero (parse barato), fallback a
  `fs::metadata` para distinguir archivo de directorio. Si no es
  ninguno, `Error::InvalidArgs` (sin fallback silencioso).
- `ContextScope { Summary | SummaryFull | Full }` controla qué se
  carga. Default `Summary` (solo `final/*.md`); `SummaryFull`
  añade `sketches/*.json`; `Full` camina el run dir entero con
  cap 4 MiB por archivo.
- `LoadedContext { parent_run_id, shared_brief_hash, brief_excerpt, context_refs }`
  se inyecta en `RunContext::with_context(...)`. El
  `IntakePhase` prepende `[context]...[/context]` al prompt del
  LLM y estampa el bloque verbatim sobre `brief.json#context_block`.
- SHA-256 sobre la concatenación canónica separada por `\x1f`
  produce el `shared_brief_hash` que se persiste en
  `runs.shared_brief_hash`.
- BLAKE3 por archivo produce el `shasum` que va a
  `run_context_refs.shasum`.

**`moagan continue --run-id <id> [--switch-provider <name>] [--switch-api-key <spec>] [--skip-checkpoint]`**

- Carga el `manifest.json` del run origen.
- `--switch-provider`: estampa el cambio sobre `manifest.provider`
  y registra en `provider_changes` con razón
  `'user --switch-provider'`.
- `--switch-api-key`: resuelve `env:VAR`, `file:path`, o literal;
  rechaza `prompt:` (sin `dialoguer` por la no-go list). Logea
  la versión redactada (`head***tail`) + prefijo SHA-256 de 8
  chars para auditoría.
- `--skip-checkpoint`: registra `checkpoint:skipped` en
  `provider_changes`.
- `Db::last_completed_phase(run_id)` devuelve la última fase
  con `status='end'`. `Pipeline::resume(canonical, last_phase)`
  filtra el pipeline canónico para saltarse fases cuyo índice
  canónico sea `<= last_phase`.

**`moagan resume <run_id>`**: alias de `continue` sin los flags
de switch. Implementado como
`run_continue(run_id, ContinueOptions::default())`.

**`moagan rerun <run_id> [--matrix-override <json>] [--same-config]`**

- Clona el manifest con `run_id` fresco, `parent_run_id = old`,
  `status = "created"`, `phases = []`.
- `--matrix-override` aplica un deep-merge de JSON sobre un
  target sintético (preparado para un bloque `execution_policy`
  futuro; hoy el patch puede tocar `brief.problem` y otros
  placeholders).
- `run_siblings` se actualiza con `relation='rerun'`.
- El pipeline arranca desde `intake` (rerun no resume; re-corre).

**`moagan import --source-path <dir> [--target-runs-dir <dir>]`**

- Lee el `manifest.json` del origen, valida el `run_id`, mueve
  el run dir al destino con `fs::rename` (o copy+delete si EXDEV).
- Error si el destino ya tiene el mismo run id (rerun es la vía
  explícita para sobreescribir).
- Re-mirror de `run_context_refs` y `runs` rows.

### Limitaciones documentadas

1. `--matrix-override` no aplica sobre un `execution_policy`

## Sub-fase N — ✅ Sandbox hardening

Implemented in `feat/v0.4-phase-n-sandbox-hardening` (seven signed
commits). This partial D.11 hardening adds four additive controls to
the existing subprocess sandbox while retaining the validator-facing
`SandboxStatus` classifications:

- **D.11.4 — bounded output:** `DEFAULT_OUTPUT_CAP_BYTES` is 64 KiB
  per stream. Independent async readers signal the parent, the child is
  killed as soon as stdout or stderr exceeds the cap, and the call
  returns `SandboxError::OutputTruncated`.
- **D.11.5 — command profiles:** `CommandConfig` and the static
  `COMMAND_CONFIGS` table describe Rust, Python, TypeScript, and SQL
  binaries, argument limits, output caps, timeouts, and network policy
  metadata. `config_for(name)` provides the stable lookup.
- **D.11.6 — argv privacy:** `strip_secrets` applies the shared redact
  policy to recognized API-key and Bearer prefixes immediately before
  spawn. Argument count and layout remain unchanged, and the recorded
  command string is sanitized too.
- **D.11.16 — binary preflight:** `verify_binary_exists` checks absolute
  paths and PATH entries before spawn, returning
  `SandboxError::BinaryNotFound(String)` for unresolved binaries. The
  legacy `SandboxStatus::NotFound` result remains available to validators.
